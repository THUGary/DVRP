# Adversarial V2: Co-evolution Training

Co-evolution training framework for V2Planner (POMO-based) and Diffusion Generator.

## Overview

This framework implements adversarial co-evolution training where:

1. **Planner Training Phase**: The planner learns to solve VRP instances generated by multiple versions of the generator. By sampling from ALL historical generator versions, we prevent **policy cycling** where the planner only learns to solve the latest generator's distributions.

2. **Generator Training Phase**: The generator learns to produce demand distributions that the current planner struggles to solve (adversarial). This pushes the generator to find weaknesses in the planner.

The alternating training creates an arms race that improves both models over time.

## Code Reuse

This module reuses existing training functions:

| Component | Reused From |
|-----------|-------------|
| Planner training (POMO) | `training_v2/train_static.py` - `train_one_batch()`, `generate_random_problems()` |
| Generator adversarial training | `training/generator/adversarial_trainer.py` - `_generate_demands()`, `rollout_episode()` |

## Algorithm

```
Initialize planner P and generator G_0
Register G_0 in version registry

for cycle in range(num_cycles):
    # Phase 1: Train Planner
    for epoch in range(planner_epochs):
        for batch:
            Sample G_v from Registry (all versions)
            Generate demands using G_v
            Update P with REINFORCE (POMO baseline)
    Save P checkpoint

    # Phase 2: Train Generator (Adversarial)
    for epoch in range(generator_epochs):
        Generate demands using G
        Rollout with P -> planner_reward
        generator_reward = -planner_reward
        Update G to maximize generator_reward
    
    Save G as G_{cycle+1}
    Register G_{cycle+1} in Registry
```

## Static vs Dynamic Mode

- **Static Mode**: All demands appear at `t=0` with `deadline=max_time`. This is standard CVRP where all customers are known upfront.

- **Dynamic Mode**: Demands appear at different times with varying deadlines. The diffusion model generates `(t, x, y, c, lifetime)` tuples.

## Usage

### Command Line

```bash
# Static VRP training
python -m adversarial_v2 --mode static --num-cycles 10

# Dynamic VRP training  
python -m adversarial_v2 --mode dynamic --num-cycles 20

# With pretrained models
python -m adversarial_v2 --mode static \
    --planner-checkpoint checkpoints/static_vrp_v2/best_n20.pt \
    --generator-checkpoint checkpoints/diffusion_model.pth \
    --num-cycles 10

# Full options
python -m adversarial_v2 --help
```

### Python API

```python
from adversarial_v2 import coevolution_loop, CoevolutionConfig

# Simple usage
config = CoevolutionConfig(
    mode="static",
    num_cycles=10,
    planner_epochs_per_cycle=5,
    generator_epochs_per_cycle=5,
)
history = coevolution_loop(config)

# Or use convenience function
from adversarial_v2 import run_coevolution
history = run_coevolution(
    mode="static",
    num_cycles=10,
    save_dir="checkpoints/my_run",
)
```

## Configuration Options

### CoevolutionConfig

| Parameter | Default | Description |
|-----------|---------|-------------|
| `mode` | "static" | "static" or "dynamic" |
| `num_cycles` | 10 | Number of co-evolution cycles |
| `planner_epochs_per_cycle` | 5 | Planner training epochs per cycle |
| `generator_epochs_per_cycle` | 5 | Generator training epochs per cycle |
| `version_sample_policy` | "latest_biased" | "uniform", "latest_biased", or "all" |
| `latest_bias` | 0.7 | P(sample latest) when using latest_biased |
| `device` | "cuda" | Training device |
| `save_dir` | "checkpoints/adversarial_v2" | Checkpoint directory |

### Version Sampling Policies

To prevent policy cycling, we sample from multiple generator versions:

- **uniform**: Equal probability for all versions
- **latest_biased**: Higher probability (70% default) for latest version
- **all**: Round-robin through all versions in each epoch

### File Descriptions

| File | Description |
|------|-------------|
| `__init__.py` | Package entry point. Exports all public APIs (`CoevolutionConfig`, `coevolution_loop`, `PlannerTrainer`, etc.) |
| `__main__.py` | Enables `python -m adversarial_v2` by calling `cotrain.main()` |
| `cotrain.py` | CLI interface with argument parsing (`argparse`). Builds config from command-line args and calls `coevolution_loop()` |
| `config.py` | Dataclasses for configuration: `CoevolutionConfig` (main config) and `EnvironmentConfig` (grid/agent settings) |
| `registry.py` | `GeneratorRegistry` class that tracks all generator versions. Enables multi-version sampling to prevent policy cycling |
| `demand_converter.py` | `DemandConverter` class that converts diffusion model output `(t, x, y, c, lifetime)` to `DemandTuple` for static/dynamic VRP |
| `train_planner.py` | `PlannerTrainer` class. Trains `StaticVRPModel` using POMO with demands from diffusion generator |
| `train_generator.py` | `GeneratorTrainer` class. Adversarial training of `DemandDiffusionModel` to maximize planner difficulty |
| `coevolution.py` | Main `coevolution_loop()` function that alternates between planner and generator training |

## Key Design Decisions

1. **Multi-version sampling**: During planner training, we sample from ALL generator versions (not just latest) to prevent the planner from overfitting to one distribution.

2. **REINFORCE with POMO baseline**: The planner uses the POMO self-competitive baseline (reward - mean_reward) for low-variance gradient estimation.

3. **EMA baseline for generator**: The generator uses exponential moving average baseline for stable adversarial training.

4. **Lazy model loading**: Models are loaded on first use to reduce memory footprint.

5. **Checkpoint registry**: JSON-based registry tracks all generator versions with metadata for reproducibility.
